# Adversarial PR Review → 머지 블로커 코멘트

codex 가 적대적으로 리뷰하고, Opus 5 가 **머지 블로커만** 걸러 표로 정리해 PR 에 코멘트로 남긴다.

| 역할 | 주체 | 하는 일 |
|------|------|---------|
| 리뷰어 | codex `adversarial-review` | 구현 방식·설계 선택·가정을 공격 |
| 필터 | 이 세션 (Opus 5) | 체크아웃, codex 실행, 머지 블로커 선별, 해결 방안 작성, 코멘트 등록 |

Opus 5 는 **직접 리뷰하지 않는다.** codex 가 뱉은 것 중에서 고르고, 각각에 대한 해결 방안을 붙인다.

## 입력

- **브랜치** — 체크아웃할 브랜치. 필수.
- **PR 번호** — 리뷰 대상 PR. 필수.

둘 중 하나라도 없으면 물어본다. 추측하지 않는다.

## 절차

### 1. 체크아웃

체크아웃 전에 워킹 트리를 확인한다.

```bash
git status --short
```

- **커밋 안 된 변경이 있으면 멈추고 사용자에게 알린다.** 체크아웃은 남의 작업을 날릴 수 있다. stash 를 임의로 하지 않는다.
- 깨끗하면 진행한다.

```bash
git fetch origin
git checkout <브랜치>
git pull --ff-only
```

리뷰가 끝나도 원래 브랜치로 되돌리지 않는다. 보통 이어서 수정하게 된다.

### 2. PR 메타 확인

```bash
gh pr view <n> --json number,title,url,baseRefName,headRefName,additions,deletions,changedFiles
```

- `headRefName` 이 방금 체크아웃한 브랜치와 다르면 **멈추고 사용자에게 알린다.** 엉뚱한 코드를 리뷰하게 된다.
- `baseRefName` 을 base ref 로 쓴다. 아래에서 `origin/<baseRefName>` 형태로 넘긴다.

### 3. codex adversarial-review 실행

`/codex:adversarial-review` 슬래시 커맨드는 `disable-model-invocation` 이라 에이전트가 호출할 수 없다. 그 커맨드가 실행하는 companion 스크립트를 직접 돌린다.

```bash
CODEX_ROOT=$(ls -d ~/.claude/plugins/cache/openai-codex/codex/*/ | sort -V | tail -1)
node "${CODEX_ROOT}scripts/codex-companion.mjs" adversarial-review --wait --base origin/<base> --scope branch
```

- `CODEX_ROOT` 가 안 잡히면 codex 플러그인이 없는 것이다. 임의로 다른 경로를 찾지 말고 사용자에게 알린 뒤 멈춘다.
- 이 스크립트는 PR 번호를 받지 않는다. 체크아웃 + `--base` 로 대상이 정해지므로 1·2단계 순서가 중요하다.
- 수 분 걸린다. 출력이 없다고 실패가 아니다. 백그라운드로 돌렸으면 `BashOutput` 으로 끝까지 수거한다.

### 4. 머지 블로커 선별

codex 지적을 하나씩 통과시킨다. **아래를 전부 만족해야 블로커다.**

- diff 에 실제로 있는 코드다. codex 가 추측으로 만든 코드가 아니다 — 의심되면 파일을 직접 열어 확인한다.
- 구체적 실패 시나리오가 성립한다. 어떤 입력/상태 → 어떤 잘못된 결과인지 쓸 수 있다.
- 그 실패가 **머지 후 프로덕션에서 터지거나 데이터·보안이 깨진다.**

나머지는 전부 버린다. major / minor / 취향 문제 / 리팩터링 제안은 코멘트에 넣지 않는다. 블로커 목록에 노이즈가 섞이는 순간 이 코멘트는 안 읽힌다.

각 블로커에 **추천 해결 방안**을 한 줄로 붙인다. 코드를 고치는 것이 아니라 무엇을 어떻게 바꾸면 되는지 지시한다.

### 5. 코멘트 등록

먼저 표를 사용자에게 보여준다. 그다음 등록한다.

```bash
gh pr comment <n> --body-file <파일>
```

- 본문은 heredoc 으로 임시 파일에 쓰고 `--body-file` 로 넘긴다. `--body` 에 여러 줄 마크다운을 인라인으로 넣지 않는다.
- **블로커가 0이면 그 사실을 한 줄로 코멘트한다.** 표는 생략한다.

## 코멘트 형식

```markdown
## 🚫 머지 블로커 (codex adversarial-review)

| # | 위치 | 문제 | 실패 시나리오 | 추천 해결 방안 |
|---|------|------|---------------|----------------|
| 1 | `src/a.ts:42` | 락 없이 카운터 증가 | 동시 요청 2건 → 하나가 유실 | `Atomics.add` 로 교체하거나 트랜잭션 안으로 이동 |

블로커 N건. 전부 해결 전에는 머지하지 않는다.
```

- 셀 안에서 줄바꿈하지 않는다. 표가 깨진다. 길면 `<br>` 를 쓴다.
- 위치는 반드시 `파일:줄`. "인증 로직 부근" 같은 건 위치가 아니다.
- codex 원문을 그대로 붙이지 않는다. 표에 맞게 다시 쓴다.

**파일을 고치지 않는다.** 이 스킬의 산출물은 코멘트다. 수정은 사용자가 따로 요청할 때 진행한다.

## 하지 말 것

- 더러운 워킹 트리에서 체크아웃 강행하기. 멈추고 알린다.
- Opus 5 가 직접 리뷰해서 항목을 추가하기. 선별과 해결 방안이 Opus 5 의 일이다.
- major / minor 를 표에 섞기. 블로커만 남기는 것이 이 스킬의 전부다.
- codex 가 조용하다고 실패로 판정하고 넘어가기. 수 분 걸린다.
- 사용자에게 안 보여주고 바로 코멘트 등록하기.
